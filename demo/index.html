01 / UNDERSTAND

你们到底要完成什么？

实现处理文件操作的 Rust 程序，并证明系统里的普通工具可以使用它。

案例：可恢复的小组资料目录

TeamFS 启动时生成 welcome.txt 和 notes/example.txt。你可以建目录、写笔记、改名和删除。目录看起来与普通目录一样，内容由 TeamFS 提供。当前版本支持 SQLite 增量保存、快照、文件及整目录恢复、回收站、独立备份和差异查询；文件内容按需读取，可选定时同步。

FUSE 让内核把文件请求转给用户空间。fuse-rs 负责通信和请求分发；你们实现 Filesystem trait，决定每个请求怎样处理。

课程成果由三部分组成：能运行的案例、可解释的原理、可复现的演示。先理解一个读取和一个写入请求，再逐步补齐其他操作。

Rust

编写文件系统逻辑的语言。所有权、类型和 Result 帮助管理数据与错误。

FUSE

内核与用户空间文件系统之间的桥梁；通过 /dev/fuse 通信。

挂载点 Mountpoint

访问文件系统的目录入口。程序挂载后，这个目录显示虚拟内容。

inode

一个节点的身份编号。名字可以变化，重命名时身份保持不变。

用户空间

TeamFS 像普通应用一样运行；内核需要它返回文件数据和属性。

回调 Callback

收到请求后执行的方法，如 lookup、read、write、readdir。

为什么 cat 能读取 Rust 的内存？
cat 请求内核读取挂载点里的文件。内核经 FUSE 把请求发给 TeamFS；read 回调从 Vec<u8> 取出字节，用 reply.data 回复，再由内核返回给 cat。
文件名和 inode 有什么区别？
目录项记录名字到 inode 的映射。rename 改变映射，inode 保留。unlink 去掉名字，打开句柄和内核引用仍可让节点继续存活。
什么时候会丢失尚未保存的文件？
默认模式正常卸载会保存；异常退出只保留最后成功同步的状态。--memory 模式不保存，重启生成预置文件。
